# Issue #15・#17 検証記録（make doctor と、ホストでのコミット）

日付: 2026-11-21。基準コミット: `33939cc`（main）。対象: [Issue #15](https://github.com/tomohiroJin/devcontainer-python/issues/15)（`make doctor`）と、[Issue #17](https://github.com/tomohiroJin/devcontainer-python/issues/17) のうち、ホストからコミットしたときにフックで失敗する件。親は [Issue #13](https://github.com/tomohiroJin/devcontainer-python/issues/13) です。

使い方は [README](../README.md) の「環境の確認（make doctor）」と「コミット前フック (prek)」にあります。ここには、決めたことと、検証の結果を記録します。

最初の実装のあと、フックと `make doctor` のそれぞれを、別の検証者が「欠陥を探す」目的で検証しました。見つかった欠陥を受けて、どちらも設計を改めています。経緯は「敵対的検証での指摘と対応」にあります。

## コミット前フック

### 変更前の問題

`make hooks`（`prek install`）が作る `.git/hooks/pre-commit` は、`prek` を呼び出します。`.git` はホストとコンテナで共有しているため、ホストでのコミットでもこのフックが動きます。ホストに prek がなければ、すべてのコミットが失敗しました。prek を入れても、Ruff と mypy がなければ失敗しました（モブプログラミングで起きた問題です）。

### 決めたこと

- **フックの本体を、このリポジトリで管理します**（[scripts/git-hooks/pre-commit](../scripts/git-hooks/pre-commit)）。`make hooks`（[scripts/git-hooks/install.sh](../scripts/git-hooks/install.sh)）が、`.git/hooks/pre-commit` にコピーします。
- **検査をするかどうかは、「Dev Container の中かどうか」で決めます。** イメージにだけあるファイル（`/etc/devcontainer/bashrc`）の有無で判断します。
  - 中: 検査を実行し、失敗したらコミットを止めます。`requirements.txt` と版が違っても実行し、その旨を表示します。
  - 外（ホスト）: 検査を省いて、コミットを通します。ホストに道具があるかどうかは見ません。
  - ホストでも検査したい人は、`git config hooks.devcontainerRunOnHost true` で有効にできます。
- **検査は `prek run` で実行します。** `prek install` が生成するフックは、prek の内部用のコマンド（`hook-impl` と、スクリプトの版番号）を呼びます。公開されているコマンドだけを使うことで、prek の更新でフックを作り直す必要がなくなります。
- 検査は、Dev Container 内の `make pre-commit` と、プルリクエストの CI（`python` ジョブの `make pre-commit`）でも行われます。CI を必須チェックにする設定は、[Issue #20](https://github.com/tomohiroJin/devcontainer-python/issues/20) に残っています。**それまでは、ホストでコミットした未検査の変更を止めるのは、CI の結果を見てからマージする運用です。**
- Issue #17 の案 (b)（ホストから、コンテナ内の検査を呼び出す）は採用していません。コンテナの名前の特定や、起動していない場合の扱いが、ホストの環境ごとに変わるためです。

### 確かめたこと

イメージの検査（`scripts/check_devcontainer.sh`）が、一時的なリポジトリで確かめます。

| 状況 | 結果 |
| --- | --- |
| コンテナ内で、問題のない変更をコミット | 検査を実行して、コミットできる |
| コンテナ内で、整形されていないファイルをコミット | `ruff format` の失敗で、コミットが止まる。直すと通る |
| コンテナ内で、`requirements.txt` の Ruff の版がイメージと違う | 版が違う旨を表示して、検査を実行する（コミットは止まる） |
| コンテナ内で、prek が PATH にない | リビルドを案内して、コミットを止める |
| ホスト（道具なし／道具が揃っている／別の版の Ruff が先頭にある） | 3通りとも、検査を省く旨を表示して、コミットできる |
| ホストで `hooks.devcontainerRunOnHost` を有効にした | 検査を実行する。prek がなければ、コミットを通す |
| `prek install` を実行した | 追跡しているファイルは変わらない。`make hooks` で元に戻る |
| `.git/hooks/pre-commit` に自分のフックがある | 退避して登録する。`make unhooks` で元に戻る |
| `.git/hooks` に他のフック（`commit-msg`）がある | そのまま動く |
| `core.hooksPath` のグローバル設定がある | このリポジトリだけ `.git/hooks` を使う設定にして、フックが動く。`make unhooks` で設定を外す |
| 最初の実装の登録（`core.hooksPath = scripts/git-hooks`）が残っている | `make hooks` で新しい方法に移る |
| 別のフック用のファイルを含むブランチをチェックアウトした | そのファイルは実行されない |
| `.pre-commit-config.yaml` のないブランチでコミット | コミットできる |

「ホスト」は、イメージの目印のファイルがない状態を、テスト用の環境変数（`DEVCONTAINER_HOOK_MARKER`）で作って確かめています。フックは POSIX の `sh` で書いています。確かめたのは、Debian の dash だけです。

## make doctor

### 決めたこと

- **イメージの検査とは分けます。** `scripts/check_devcontainer.sh` は、イメージが正しく作られたかを CI で確かめます。`make doctor` は、人や起動のたびに変わるもの（Git の設定、認証、フック、リモート）を確かめます。
- **設定を読んで推測せず、Git に実際にやらせます。**
  - 名前とメールアドレス: `git var GIT_AUTHOR_IDENT` が成功するか（設定の階層、`includeIf`、環境変数のどれで決まっていてもよい）。
  - 署名: このリポジトリの設定のまま、`git commit-tree -S` でコミットのオブジェクトに署名できるか。コミットは作らず、フックも動きません。オブジェクトは、一時的な場所に書きます。
  - 認証情報: `git credential fill` で、push 先のホストの認証情報を取得できるか。ヘルパーの並びや打ち消し（空の値）、ホストごとの設定は、Git が解釈します。取得した値は、表示も保存もしません。
- **入力待ちで止まらないようにします。** 認証情報とパスフレーズの入力は、受け付けない設定（`GIT_TERMINAL_PROMPT=0`、`GIT_ASKPASS`・`SSH_ASKPASS` を何も返さないコマンドにする）で実行します。外部のコマンドには制限時間を付けます（`timeout` がない環境では、自前の見張りで打ち切ります）。
- **出力では、設定の値を表示しません。** 表示する文字列（リモートの URL、パス、エラーの文言）は、すべて伏せる処理を通します。
- **コンテナの作成時には、自動で実行しません。** VS Code がホストの Git の設定をコピーする前に実行されると、誤った結果が出るおそれがあるためです。
- **Dev Container の外では、ツールの版と整形を確認しません。** ホストにはツールがないのが普通で、あっても版が違うためです。
- **push の権限は、`gh` で認証している場合だけ確認します。** それ以外は、認証情報を取得できることと、リモートを読み取れることまでです。

### 確かめたこと

イメージの検査が、一時的なリポジトリと、一時的なホームディレクトリで確かめます。期待する表示（`ok`・`info`・`warn`・`FAIL`）と、終了コード（`FAIL` のときだけ 1）の両方を確かめています。

| 分類 | 確かめている状態 |
| --- | --- |
| 準備ができている状態 | `warn` と `FAIL` がなく、終了コード 0 |
| 秘密を表示しない | メールアドレス、認証情報、ヘルパーのコマンドに含まれるトークン、ホームディレクトリ、URL の認証情報とクエリ文字列、SSH のリモートのユーザー名 |
| 認証情報 | 関数の形のヘルパー（VS Code が使う形）は `ok`。何も返さないヘルパー、ホストにしかないヘルパー、ヘルパーなしは、`github.com` で `FAIL`、他のホストで `warn`。ホストのヘルパーを `github.com` 用に打ち消して別のヘルパーを足した設定（`gh auth setup-git` のあとの形）は `ok` |
| 名前とメールアドレス | ないと `FAIL`。環境変数、リポジトリの設定で決まる場合は `ok` |
| 署名 | リポジトリの設定で有効にした署名が失敗すると `FAIL`。リポジトリの設定の鍵で SSH 署名できると `ok`。パスフレーズ付きの鍵は `warn`（15 秒以内に終わること）。タグの署名の失敗も `FAIL`。確認中に、グローバルの `core.hooksPath` のフックが動かないこと |
| フック | 未登録、`prek install` のフック、登録済みのフックが古い、別の `core.hooksPath` は、それぞれ `warn` |
| リモート | SSH 形式で鍵がないと `FAIL`。ssh が使う鍵のファイルがあれば `info`。`github.com` の SSH 形式は HTTPS として確認する。`origin` 以外の名前のリモートが1つだけなら、それを使う |
| 接続 | 読み取れるリモートは `ok`。取得用の URL は読めても、push 用の URL に接続できなければ `FAIL`。存在しないリポジトリには、URL の確認を案内する |
| 作業ツリー、ツール | 未整形のファイルは件数付きで `warn`。Ruff が構文を解釈できないファイルは、別の文言で `warn`。別の版のツールは `warn`、ツールがないと `FAIL`。`~/.local/bin` が PATH にないと `warn`。CRLF で登録されたファイルと `core.autocrlf=true` は `warn` |
| オプション | `--quiet` は、問題がなければ何も表示せず、あれば問題だけを表示する。不明なオプションは終了コード 2 |
| 制限時間 | `timeout` がない環境用の見張りが、子プロセスが出力を握ったまま止まったコマンドを打ち切る。標準入力を渡し、終了コードを保つ |
| リポジトリの外、所有者の不一致 | それぞれ、その旨の `FAIL` |

Dev Container の外（この検証環境）でも実行し、「ここは Dev Container の外（ホスト）です」と表示して、ツールの確認を省くことを確かめました。

## 敵対的検証での指摘と対応

最初の実装（コミット `4569ca8`）を、フックと `make doctor` に分けて、別々の検証者に渡しました。渡したのは、対象のファイル、意図した仕様、イメージで試す手順です。実装者の検証結果は渡していません。どちらも、実際のイメージで再現した結果を報告しています。

### フック（指摘10件）

最初の実装は、Git の設定（`core.hooksPath`）を、追跡しているディレクトリ（`scripts/git-hooks`）に向けていました。また、道具の版が `requirements.txt` と一致するかどうかで、検査をするかを決めていました。

| 指摘 | 対応 |
| --- | --- |
| `prek install` を実行すると、追跡しているフックが上書きされ、ホストでコミットできない状態に戻る | フックを `.git/hooks` にコピーする方法に変更。`prek install` は追跡しているファイルに触れなくなり、`make hooks` で元に戻る。`make doctor` が検出する |
| `requirements.txt` の版がイメージと違うだけで、コンテナ内の検査がすべて無効になる | 検査をするかどうかを、Dev Container の中かどうかで決めるように変更。版が違っても検査は実行する |
| `scripts/git-hooks` のないブランチでは、フックが何も動かない | コピーしたフックは、どのブランチでも動く |
| `make unhooks` を実行すると、以前の `prek install` のフックが復活して、ホストでコミットできなくなる | `make hooks` が、`prek install` のフックを置き換える |
| ホストに版の合う道具があっても、mypy が依存を見つけられないとコミットが止まる | ホストでは、道具の有無にかかわらず検査を省く。検査したい人だけが有効にする |
| `.git/hooks` にある他のフックが、黙って無効になる | `.git/hooks` をそのまま使うので、他のフックは動く。同じ名前のフックは退避して、`make unhooks` で戻す |
| ブランチをチェックアウトしただけで、そのブランチが足したフック用のファイルが、ホストで実行される | Git は、追跡しているディレクトリのファイルを直接は実行しなくなった |
| `requirements.txt` を読めないと、入っている版のまま検査が動く | 版による判定をやめたため、該当しなくなった |
| テストが甘い（道具の組み合わせを確かめていない、失敗の理由を見ていない） | 上の表の状態を追加。失敗は、`ruff format` の失敗であることまで確かめる |
| `make unhooks` の表示が、リポジトリの外などで誤っている | インストーラーをスクリプトに分け、状態に合わせて表示する |

### make doctor（指摘16件と、軽微な指摘）

最初の実装は、認証ヘルパーの設定を自前で解釈し、署名を別の一時的なリポジトリで試していました。

| 指摘 | 対応 |
| --- | --- |
| 認証ヘルパーのコマンドに含まれるトークンやパスワードを、そのまま表示する | ヘルパーのコマンドを解釈も表示もしない。`git credential fill` の結果（取得できたかどうか）だけを使う |
| 関数の形のヘルパー（VS Code が使う形）を `FAIL` にする | 同上（Git が実行する） |
| `gh auth setup-git` を実行したあとも、打ち消されたホストのヘルパーを理由に `FAIL` のままになる | 同上（打ち消しは Git が解釈する） |
| リポジトリの設定で有効にした署名が壊れていても、`ok` と表示する | このリポジトリの設定のまま署名を試す |
| 名前や署名の鍵がリポジトリの設定にあると、誤って `FAIL` にする。確認中に、関係のないフックを実行する | 同上。`git commit-tree` を使うので、フックは動かない |
| パスフレーズ付きの鍵と、認証情報の入力を求めるプログラムで、入力待ちになる。`--offline` でも止まる | 入力を受け付けない設定で実行し、制限時間を付ける。パスフレーズが必要な鍵は `warn` として知らせる |
| 所有者の不一致を検出する処理に、到達しない | リポジトリの場所を調べる時点で検出する |
| 接続の確認に取得用の URL を使うため、push できないのに `ok` になる。`origin` 以外のリモートを見ない | push に使うリモートと URL を、Git の設定から決める |
| URL の種類の判定が粗い（パスや `git://` を SSH と判定する。`~/.ssh/config` の鍵を見ない） | 判定を分け、鍵のファイルは `ssh -G` の結果で確かめる |
| 伏せ漏れ（SSH のリモートのユーザー名、パスに含まれるメールアドレスやトークン、クエリ文字列、ASCII 以外のメールアドレス、ホームディレクトリ） | 表示する文字列を、すべて同じ伏せる処理に通す。対象を広げた |
| Ruff が整形以外の理由で失敗しても、「整形されていない」と表示する | 終了コードで分け、別の文言で知らせる |
| `code` コマンドが VS Code に接続できないと、拡張がないと誤って表示する | 確認できなかった旨を `info` で知らせる |
| エラーの文言に `401` などの数字が含まれるだけで、認証の失敗と案内する | 文言の一致を、具体的な句に限る |
| push の権限の確認が、条件によって何も表示しない | 確認しなかった理由を、常に表示する |
| テストが甘い（伏せる処理や `--quiet` を無効にしても通る） | 上の表の状態を追加した |
| 軽微: `HOME` が未設定だと異常終了する、中断すると一時ディレクトリが残る、`--quiet` で空行が出る、環境変数だけの名前を `FAIL` にする、タグの署名を見ない、など | それぞれ直した |

| フックが版の違いを知らせない | 1 |
| インストーラーが既存のフックを退避しない | 2 |
| インストーラーがグローバルの `core.hooksPath` を無視する | 3 |
| コンテナ内で prek がなくてもコミットを通す | 1 |
| `make unhooks` がフックを残す | 2 |
| 伏せる処理を無効にする | 4 |
| `--quiet` を無視する | 2 |
| 不明なオプションを受け付ける | 1 |
| ツールの版の比較を無効にする | 1 |

| `core.autocrlf` の確認を無効にする | 1 |

### 対応の途中で見つけた不具合

`timeout` がない環境用の見張りを書いたあと、確かめたところ、2点の不具合がありました。どちらも直し、検査に加えています。

- 打ち切ったコマンドの子プロセスが出力を握っていると、打ち切ったあとも待ち続けました（2秒の制限で30秒かかりました）。出力をファイルに受ける形に変えました。
- 子プロセスを先に止めると、親が続きを実行することがありました（25回に数回の頻度で、検査が不安定になりました）。親を先に止める順序に変えました。

### 対応していない指摘

- **GitHub のトークン以外の秘密**: 代表的な形（GitLab、Slack、AWS のアクセスキー、`Bearer`）は足しましたが、形で判断しているため、すべての秘密は伏せられません。README に、貼る前に目を通すよう書いています。
- **リモートのホスト名とリポジトリ名**: 表示します。問題の切り分けに必要なためです。
- **認証ヘルパーが、認証情報を返すのに使えない値を返す場合**: 取得できたかどうかまでを確かめます。その認証情報で push できるかは、接続の確認と、`gh` による権限の確認で補います。

## 確かめていないこと

- **実際のホストでのコミット**（Windows の Git for Windows、macOS、WSL）。ホストの状態は、テスト用の環境変数で作りました。
- **GitHub への接続と、push の権限の確認**。検証環境から GitHub に接続できないため、接続の確認は、ディスク上のリポジトリで確かめました。`gh` で認証した場合の権限の確認は、動かしていません。
- **VS Code が設定する認証ヘルパーの、実際の文字列**。関数の形のヘルパーで確かめましたが、VS Code そのものでは確かめていません。VS Code の統合ターミナルで `make doctor` を実行すると、VS Code のヘルパーが認証情報を返すかどうかが、そのまま結果になります。その際、ホスト側で認証の画面が開くことがあります。
- **VS Code の拡張の確認**（`code --list-extensions` を使う部分）。
- **macOS と Git for Windows での動作**。bash 3.2 と BSD のコマンドで動かない書き方は避けましたが、実行はしていません。`timeout` がない場合の見張りの処理は、`timeout` を使わない状態を作って確かめました（止まったコマンドを打ち切ること、標準入力を渡すこと、終了コードを保つこと）。macOS そのものでは実行していません。
